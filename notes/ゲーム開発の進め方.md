# ゲーム開発の進め方

Claude の「AIゲーム」プロジェクトで、riku の個人開発ゲームを進めるときの決まりごとと、ハマったところ。

## 決まりごと
- [decision] 応答・コミット・コメント・PR 説明は日本語
- [decision] main から claude/〜 ブランチを切って作業し、main 向けの PR を作る。マージはしない。ただし riku が「マージして」と言ったらしてよい（PocketDungeon60 は 2026-10-08 から Claude が自分の PR をマージしてよい）
- [decision] PR 説明には (1) 変更したファイルと理由 (2) 要確認リスト (3) Unity で確認する手順（初心者でも迷わない粒度）を必ず書く
- [decision] .unity / .prefab / .asset の YAML は編集しない。.meta は作らない（Unity が生成する）
- [decision] 企画書・設計書の仕様は勝手に変えない。迷う点は「要確認」として残す
- [decision] Photon の AppId などの秘密情報はコードにもドキュメントにも書かない
- [decision] 作業はクラウド優先（2026-10-19 riku「クラウド側でもっとやって」、2026-10-23「ローカルで作業してほしくない」）。コード・コミット・push・PR はクラウドから。PC（Remote Control）は Unity での確認・ビルド・Unity が作った .meta やシーンのコミットなど、PC でしかできないことだけ

## riku の環境
- [fact] GitHub Desktop で取得し、Fetch origin → Pull origin で最新にする。最新版は ドキュメント\GitHub\<リポジトリ名>。デスクトップ\AIgame\... に古いコピーがある
- [fact] PC は DESKTOP-KP3O0QI。作業フォルダは C:\dev\AIgame。Remote Control が D:\株本 フォルダで接続されることがある
- [fact] AMD GPU のため Unity は DX11 で起動（DX12 だとクラッシュ）
- [fact] スマホは iPhone のみ（Android 実機なし）

## ハマったところ
- [problem] Unity Hub が古いコピーを開いていて「修正が反映されない」（KatsuoGame、2026-09-27）。main を開いていてブランチの変更が見えない（KatsuoGame #12、2026-10-23） → [solution] エラーや表示が古いときは、まず開いているフォルダとブランチを確認する
- [problem] AntColony はスクリプト置き場と Unity プロジェクト（AntColony-Unity）が別リポジトリ。片方だけ直しても Unity に反映されない（2026-10-18）
- [problem] PC の Remote Control とクラウドで同じブランチを二重に直した（AntColony、2026-10-23） → [solution] どちらで作業するかを先に決める
- [problem] Remote Control 側は Claude 経由の指示だけだと commit/push が止まる → [solution] riku 本人がスレッドに一言書く
- [fact] クラウドでは Unity が使えない。C# の構文チェックは tree-sitter-c-sharp でやり、Unity でしか確かめられない点は PR の確認手順に書く
- [fact] プレビュー画像を送り直すときは新しいファイル名にする（同じ名前だとアプリ側に古い表示が残る）
